## Executive Summary

v2 builds directly on the v1 foundation to bring Word (`.docx`) and PowerPoint (`.pptx`) documents into the unified parsing pipeline. 

Instead of converting files on disk or using basic text scrapers that discard tables and presentation outlines, v2 introduces `DoclingParser`. It streams raw bytes in-memory via Docling's `DocumentStream` into `DocumentConverter.convert()`. The resulting `DoclingDocument` preserves headings, tables, and slide structures, and flows straight into our existing `HybridChunker`.

```
Incoming (.docx, .pptx) ──> ParserRouter ──> DoclingParser ──> DoclingDocument ──> HybridChunker ──> TextChunk[]
```

v2 also includes two post-implementation bug fixes and one new capability discovered during real-document testing:
1. **Critical fix** — `HybridChunker.chunk()` drops section/slide titles from chunk text (Phase 0).
2. **Picture description** — embedded images in DOCX/PPTX are described by a local lightweight VLM and injected into the chunk stream (Phase 5). DeepSeek-OCR2 does **not** run on this dev machine (GTX 1650, 4GB VRAM — model requires ≥8GB). See [`parsing_architecture_plan.md`](file:///c:/Users/vaibh/OneDrive/Documents/HoneyWell/honeywell-virtual-assistant/parsing_architecture_plan.md) v6 note for the DeepSeek-OCR2/vLLM plan.

Legacy endpoints (`core/parser.py`) and v1 text parsing remain completely untouched.

## Phase 0 (Critical Fix): `contextualize()` — Section Titles in Chunk Text

### What is happening
Real-document testing revealed two related gaps in `_split_docling()`:

**Gap A** — `HybridChunker.chunk()` returns `DocChunk.text` containing only the body text. Section headings and slide titles are stored in `chunk.meta.headings`. Using `chunk.text` directly silently strips every heading from the embedded text.

**Gap B** — Any slide or section that is a heading with no body (e.g., a section-divider slide) produces zero raw chunks from `HybridChunker`. Even after fixing Gap A, these slides would still be completely absent from the chunk stream because no `DocChunk` is ever emitted for them.

### Fix (two parts in `core/chunker.py → _split_docling()`)

**Part 1** — Replace `chunk.text` with `chunker.contextualize(chunk)` (not `serialize()`, which is deprecated in this Docling version):
```python
# Before (buggy): heading context silently lost
text = chunk.text.strip() if hasattr(chunk, "text") else str(chunk)

# After (correct): heading path prepended to body text
text = chunker.contextualize(chunk).strip()
# e.g. 'Architecture Overview\nUpload -> Parse -> Embed -> Qdrant.'
```

**Part 2** — After `list(chunker.chunk(doc))`, collect covered headings, then walk `doc.texts` and inject a synthetic chunk for any `title`/`section_header` item that produced no chunk:
```python
covered = {h for c in raw_chunks for h in getattr(c.meta, 'headings', [])}
for item in doc.texts:
    if item.label in ('title', 'section_header'):
        if item.text.strip() and item.text.strip() not in covered:
            synthetic_texts.append(item.text.strip())  # heading-only slide
```

## Phase 1: Implement `DoclingParser` (`.docx` & `.pptx`)

### What is happening
Create `parsers/docling_parser.py` subclassing `BaseParser`. It takes raw file bytes, wraps them in an in-memory `DocumentStream(name=filename, stream=io.BytesIO(file_bytes))`, and runs them through Docling's `DocumentConverter.convert()`. 

This avoids writing temporary files to disk while natively extracting document hierarchy, tables from `.docx`, and slide layouts from `.pptx`.

### Key Implementation Snippet
```python
# parsers/docling_parser.py
import io
from docling.document_converter import DocumentConverter
from docling_core.types.io import DocumentStream
from docling_core.types.doc import DoclingDocument
from .base import BaseParser

class DoclingParser(BaseParser):
    SUPPORTED_EXTENSIONS = frozenset({".docx", ".pptx"})

    def __init__(self) -> None:
        self._converter = DocumentConverter()

    def can_handle(self, ext: str) -> bool:
        return ext.lower() in self.SUPPORTED_EXTENSIONS

    def parse(self, file_bytes: bytes, filename: str, **kwargs) -> DoclingDocument:
        stream = DocumentStream(name=filename, stream=io.BytesIO(file_bytes))
        result = self._converter.convert(stream)
        return result.document
```

### Tests & Verification
- **What is tested** (`tests/test_parsers/test_docling_parser.py`):
  - `.docx` parsing: creates in-memory document with headings, paragraphs, and a table; asserts text and table contents exist in `DoclingDocument`.
  - `.pptx` parsing: creates in-memory presentation with slide title and body text; asserts slide content is extracted.
  - `can_handle()` contract: returns `True` for `.docx`, `.pptx`, and uppercase `.DOCX`, `.PPTX`; returns `False` for `.pdf`, `.txt`, etc.

## Phase 5: Local Lightweight Picture Description

### What is happening
Embedded images in DOCX/PPTX files never reach the chunk stream — `HybridChunker` only processes `.texts` and `.tables`; `.pictures` is a separate collection. v2 adds lightweight local picture description using Docling's built-in VLM support.

**Hardware constraint**: DeepSeek-OCR2 requires ≥8GB VRAM. This machine has a GTX 1650 (4GB). The v6 vLLM migration plan targets this model on production hardware — see [`parsing_architecture_plan.md`](file:///c:/Users/vaibh/OneDrive/Documents/HoneyWell/honeywell-virtual-assistant/parsing_architecture_plan.md). For v2, we use:
- **Primary**: SmolVLM-256M via Docling's built-in `smolvlm` preset (runs in-process, ~256MB VRAM)
- **Escalation**: Granite-Vision-3.3-2B via Ollama `granite_vision` preset if SmolVLM descriptions are too generic

### Key Config Additions (`config.py`)
```python
# Parsing Architecture v2 — picture description (DOCX/PPTX)
picture_description_preset: str = os.getenv("PICTURE_DESCRIPTION_PRESET", "smolvlm")
picture_description_prompt: str = os.getenv(
    "PICTURE_DESCRIPTION_PROMPT",
    "Describe this image in 2-3 sentences. Be concise and accurate."
)
enable_picture_description: bool = (
    os.getenv("ENABLE_PICTURE_DESCRIPTION", "false").lower() == "true"
)
```

### Key Implementation (in `parsers/docling_parser.py`)

**5a — Enable VLM on conversion (guarded by `ENABLE_PICTURE_DESCRIPTION`)**:
```python
# Wrapped in try/except — known Docling bug where do_picture_classification
# throws on native chart shapes (not raster images)
if settings.enable_picture_description:
    try:
        result = self._converter_with_vlm.convert(stream)
    except Exception:
        logger.warning("Picture description failed, retrying without VLM")
        result = self._converter.convert(stream)
```

**5b — Inject descriptions into doc.texts before chunking (Tasks 8, 9, 11, 12)**:
Docling stores VLM descriptions in both `picture.meta.description` (canonical, read by `MarkdownSerializer` and `HybridChunker`) and `picture.annotations` (deprecated). Descriptions are cleaned, tagged, and assigned to both fields as well as injected as `DocItemLabel.CAPTION` text items:
```python
for picture in doc.pictures:
    raw_text = ""
    meta_desc = getattr(getattr(picture, "meta", None), "description", None)
    if meta_desc and getattr(meta_desc, "text", None):
        raw_text = meta_desc.text
    elif getattr(picture, "annotations", None):
        for ann in picture.annotations:
            if isinstance(ann, PictureDescriptionData) and getattr(ann, "text", None):
                raw_text = ann.text
                break

    if not raw_text:
        continue

    # Strip complete tokens like <end_of_utterance>
    cleaned = re.sub(r"<[a-z_]{1,40}>", "", raw_text)
    # Strip dangling/unclosed token at end of string (e.g. <end_of_utteranc)
    cleaned = re.sub(r"<[a-z_]{0,40}\s*$", "", cleaned).strip()
    if not cleaned:
        continue

    tagged_description = f"[Figure description] {cleaned}"

    # 1. Update canonical picture.meta.description so HybridChunker picks it up
    if meta_desc is not None:
        meta_desc.text = tagged_description

    # 2. Update deprecated picture.annotations
    if getattr(picture, "annotations", None):
        for ann in picture.annotations:
            if isinstance(ann, PictureDescriptionData):
                ann.text = tagged_description

    # 3. Inject CAPTION TextItem into doc
    try:
        doc.add_text(
            label=DocItemLabel.CAPTION,
            text=tagged_description,
            parent=picture,
        )
    except Exception as exc:
        logger.warning(
            f"Picture description failed for {picture.self_ref}: {exc}"
        )
```

- **Task 8 & 11 (Special & Truncated Token Stripping)**: Docling's `smolvlm` preset defaults `skip_special_tokens=False`. The raw VLM output for Slide 16 was verbatim `'Thankyou!<end_of_utteranc'`. The two-stage regex strips both complete tokens (`<end_of_utterance>`) and unclosed trailing token fragments (`<end_of_utteranc`) without touching legitimate angle bracket content.
- **Task 9 (Failure Logging Guard)**: Any failure in `doc.add_text()` logs `logger.warning(f"Picture description failed for {picture.self_ref}: {exc}")` in a separate branch with no shared variable, guaranteeing no log messages leak into chunk content.
- **Task 12 (`[Figure description]` tag & `source` metadata)**:
  - *Tag Prefix*: Docling's `HybridChunker` serializes `PictureItem` via `picture.meta.description.text`. Updating `picture.meta.description.text = tagged_description` ensures `[Figure description]` appears in the chunk text.
  - *Metadata Key*: In `core/chunker.py`, chunks containing `[Figure description]` or `DocItemLabel.PICTURE` items have `"source": "image_description"` added to their metadata dict.
