## Executive Summary

This plan introduces the foundation for a unified document parsing architecture based on Docling's `DoclingDocument`. Instead of ad-hoc text extraction, every supported file type produces a structured `DoclingDocument` that flows into a token-aware `HybridChunker`.

v1 implements the base infrastructure, plaintext/markdown parsing, routing, and backward-compatible chunking. Existing routes and `core/parser.py` remain untouched.

```
Incoming File (.txt, .md) ──> ParserRouter ──> TextParser ──> DoclingDocument ──> HybridChunker ──> TextChunk[]
```

## Phase 1: Core Parsers Package & `BaseParser` Interface

### What is happening
Create a dedicated `parsers/` package with an abstract base class `BaseParser`. Every parser must implement two methods:
1. `can_handle(file_extension)`: returns whether this parser supports the given extension.
2. `parse(file_bytes, filename, **kwargs)`: parses raw bytes and returns a structured `DoclingDocument`.

### Key Interface Snippet
```python
# parsers/base.py
from abc import ABC, abstractmethod
from docling_core.types.doc import DoclingDocument

class BaseParser(ABC):
    @abstractmethod
    def can_handle(self, ext: str) -> bool:
        """Return True if parser supports the extension (e.g., '.txt')."""
        ...

    @abstractmethod
    def parse(self, file_bytes: bytes, filename: str, **kwargs) -> DoclingDocument:
        """Parse raw file bytes into a DoclingDocument."""
        ...
```

## Phase 2: `TextParser` Implementation (Plaintext & Markdown)

### What is happening
Implement `TextParser` in `parsers/text.py` for `.txt` and `.md` files. It decodes byte streams with fallback handling (UTF-8, Latin-1) and wraps the content into a `DoclingDocument` using Docling's `DocumentConverter.convert_string()`. Markdown headings are preserved as native Docling section levels.

### Key Interface Snippet
```python
# parsers/text.py
class TextParser(BaseParser):
    SUPPORTED_EXTENSIONS = {".txt", ".text", ".md", ".markdown"}

    def parse(self, file_bytes: bytes, filename: str, **kwargs) -> DoclingDocument:
        text = self._decode_bytes(file_bytes)
        result = self._converter.convert_string(text, format=input_format)
        return result.document
```

## Phase 3: `ParserRouter` Dispatcher

### What is happening
Implement `ParserRouter` in `parsers/router.py`. It inspects file extensions and delegates parsing to the matching registered parser. In v1, it automatically registers `TextParser` for `.txt` and `.md`, raising a descriptive `UnsupportedFileError` for unsupported extensions (like `.pdf` or `.docx`, which will be added in subsequent phases).

### Key Interface Snippet
```python
# parsers/router.py
class ParserRouter:
    def get_parser(self, filename_or_ext: str) -> BaseParser:
        ext = self._normalize_ext(filename_or_ext)
        for parser in self._parsers:
            if parser.can_handle(ext):
                return parser
        raise UnsupportedFileError(f"No parser available for '{ext}'")

    def parse(self, file_bytes: bytes, filename: str, **kwargs) -> DoclingDocument:
        parser = self.get_parser(filename)
        return parser.parse(file_bytes, filename, **kwargs)
```

### Tests & Verification
- **What is tested**:
  - Routing `.txt` and `.md` files to `TextParser`.
  - Case-insensitivity (e.g., `.TXT`, `.MD`).
  - Correct exception thrown for unknown types (`.xyz`, `.pdf`).
  - Parsing directly through `router.parse()` yields a valid `DoclingDocument`.
- **Run command**:
```powershell
pytest tests/parsers/test_router.py -v
```

## Phase 4: `HybridChunker` Integration in `core/chunker.py`

### What is happening
Upgrade `Chunker.split()` to support `DoclingDocument` inputs using Docling's `HybridChunker`. 
- **Backward compatibility**: If passed legacy `list[tuple[int, str]]` page tuples, it delegates to the existing recursive text chunker.
- **New capability**: If passed a `DoclingDocument`, it runs `HybridChunker` using the tokenizer defined in config, producing semantic chunks enriched with document structure and token limits.

### Key Interface Snippet
```python
# core/chunker.py
def split(self, pages_or_doc, file_id: str, filename: str) -> list[TextChunk]:
    if isinstance(pages_or_doc, DoclingDocument):
        return self._split_docling(pages_or_doc, file_id, filename)
    else:
        # Legacy list[tuple[int, str]] fallback
        return self._split_legacy(pages_or_doc, file_id, filename)
```

### Tests & Verification
- **What is tested**:
  - Legacy page-list chunking produces identical chunks as before (zero regression).
  - `DoclingDocument` inputs are successfully split into `TextChunk` models with correct `chunk_index`, `metadata`, and content.
  - Chunk character and token lengths remain within configured bounds.
- **Run command**:
