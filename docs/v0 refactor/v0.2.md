# Version 0.2: Foundation & Resilience

## Objective
Establish a solid operational foundation by centralizing application configuration, upgrading FastAPI lifecycle events to modern standards, adding global error handling, and eliminating dead code—without altering any pipeline logic.

---

## 1. Centralized Configuration (`config.py`)

### Problem in v0.1
`os.getenv(...)` calls are scattered across `main.py`, `uploader.py`, `retriever.py`, `generator.py`, and `chunker.py`. Defaults are inconsistent (e.g., `MINIO_BUCKET` defaults to `honeywell-documents` in `uploader.py`, but `docker-compose.yml` provides `honeywell-files`).

### Technical Specification
Create `config.py` using a typed dataclass or settings class:

```python
# config.py
import os
from dataclasses import dataclass

@dataclass(frozen=True)
class Settings:
    # MinIO
    minio_endpoint: str = os.getenv("MINIO_ENDPOINT", "minio:9000")
    minio_bucket: str = os.getenv("MINIO_BUCKET", "honeywell-files")
    minio_access_key: str = os.getenv("MINIO_ACCESS_KEY", "")
    minio_secret_key: str = os.getenv("MINIO_SECRET_KEY", "")

    # ChromaDB
    chroma_host: str | None = os.getenv("CHROMA_HOST")
    chroma_port: int = int(os.getenv("CHROMA_PORT", "8000"))
    chroma_path: str = os.getenv("CHROMA_PATH", "./chroma_data")
    chroma_collection: str = os.getenv("CHROMA_COLLECTION", "my_documents")

    # Ollama
    ollama_host: str = os.getenv("OLLAMA_HOST", "ollama")
    ollama_port: str = os.getenv("OLLAMA_PORT", "11434")
    ollama_model: str = os.getenv("OLLAMA_MODEL", "llama3.2:3b")

    # RAG & Ingestion Parameters
    chunk_size: int = int(os.getenv("CHUNK_SIZE", "1000"))
    chunk_overlap: int = int(os.getenv("CHUNK_OVERLAP", "200"))
    retrieval_k: int = int(os.getenv("RETRIEVAL_K", "5"))

settings = Settings()
```

### Affected Files
- `core/uploader.py`: Replace inline `os.getenv` with `settings`.
- `core/retriever.py`: Replace inline `os.getenv` with `settings`.
- `core/generator.py`: Replace inline `os.getenv` with `settings`.
- `core/chunker.py`: Replace inline `os.getenv` with `settings`.
- `main.py`: Replace `os.getenv("RETRIEVAL_K", "5")` with `settings.retrieval_k`.

## 2. Modern Lifespan Management

### Problem in v0.1
`main.py` uses `@app.on_event("startup")`, which is deprecated in modern FastAPI.

### Technical Specification
Use `contextlib.asynccontextmanager` to define the application lifecycle:

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI

@asynccontextmanager
async def lifespan(app: FastAPI):
    # Startup: ensure required storage bucket exists
    uploader.ensure_bucket()
    yield
    # Shutdown logic (if needed in future)

app = FastAPI(title="Honeywell RAG", version="1.0.0", lifespan=lifespan)
```

## 3. Centralized Exception Handlers

### Problem in v0.1
Every endpoint wraps code in identical `try...except ValueError... except StorageError...` blocks.

### Technical Specification
Register global exception handlers on the `FastAPI` instance:

```python
from fastapi import Request
from fastapi.responses import JSONResponse
from core import StorageError, GenerationError

@app.exception_handler(ValueError)
async def value_error_handler(request: Request, exc: ValueError):
    return JSONResponse(status_code=400, content={"detail": str(exc)})

@app.exception_handler(StorageError)
async def storage_error_handler(request: Request, exc: StorageError):
    return JSONResponse(status_code=502, content={"detail": str(exc)})

@app.exception_handler(GenerationError)
async def generation_error_handler(request: Request, exc: GenerationError):
    return JSONResponse(status_code=503, content={"detail": str(exc)})
```

This cleans repetitive exception boilerplate from all route handlers.
