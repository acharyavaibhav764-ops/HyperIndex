## Issues found

### Issue 1 (Critical) — `page` / `page_numbers` are always `None` / `[]`

**Root cause, confirmed empirically:** `_merge_pages()` (pdf_router.py:250-274)
joins every page's markdown string with `\n\n---\n\n` and feeds the *combined*
text through `DocumentConverter(allowed_formats=[InputFormat.MD])` **once**.
Docling's Markdown backend builds `DoclingDocument` items (`add_text`,
`add_heading`, …) without ever passing `prov=`. Any item added to a
`DoclingDocument` without an explicit `prov` defaults to `prov=[]`:

```
>>> item = doc.add_text(label=DocItemLabel.TEXT, text='hello world')
>>> item.prov
[]
```

Your `core/chunker.py::_split_docling()` (lines ~185-195) reads
`item.prov[0].page_no` and explicitly filters on `if getattr(item, "prov", None)`
— an empty list is falsy, so `pages` is always `[]` and `page` is always `None`.
This is upstream of `chunker.py`; the extraction logic there is already correct
and needs no change.

**Reproduction output** (offline, real `docling_core.DoclingDocument` +
`HybridChunker`, chunker.py's exact extraction code):

```
CURRENT BEHAVIOUR (today's _merge_pages, no prov set):
{'text': 'Installation Guide...',  'page': None, 'page_numbers': []}
{'text': 'Troubleshooting...',     'page': None, 'page_numbers': []}
{'text': 'Warranty Information...','page': None, 'page_numbers': []}

FIX (per-page prov stamped before merge):
{'text': 'Installation Guide...',  'page': 1, 'page_numbers': [1]}
{'text': 'Troubleshooting...',     'page': 2, 'page_numbers': [2]}
{'text': 'Warranty Information...','page': 3, 'page_numbers': [3]}
```

### Issue 2 (High) — image-route threshold is dimensionally miscalibrated

`_triage_page()` (pdf_router.py:146-169):

```python
text_ratio = text_len / area if area > 0 else 0.0     # area = width_pt * height_pt
if has_image and text_ratio < settings.pdf_text_ratio_threshold:  # default 0.05
    return "image"
```

`area` is in points² (~501,000 for A4, ~484,700 for Letter). For `text_ratio` to
reach the 0.05 threshold on an A4 page, a single page needs **≈25,000 characters**
(~4,000+ words) of extracted text. A normal body-text page holds roughly
3,000–4,000 characters. Your own test suite shows this: to hit the "text despite
image" branch, `test_triage_returns_text_when_text_dense` has to fabricate
`"a" * 50_000` — a page with 50,000 characters isn't realistic. In production this
means **any page with an image — even one dense paragraph plus a small logo —
always routes to the SmolVLM tier**, never to the cheap PyMuPDF4LLM path the
triage was designed to prefer. This isn't a corner case; it's the default outcome
for essentially every image-bearing page, which also quietly inflates SmolVLM
load (relevant since v6 is planned to swap in DeepSeek-OCR2 under the same tier).

### Issue 3 (Low, docs only) — stale "v5 scope note" comments

`_docling_page()` and `_smolvlm_page()` docstrings still say "exports the full
document, not just page_no... deferred to v5.1" — but `parse()` already isolates
single-page bytes via `_single_page_bytes()` before calling either method (your
duplication-bug fix). The comments describe a bug that's already fixed and
point at this exact version ("v5.1") as where it'd be addressed — safe and
in-scope to correct now, not a violation of the comment-preservation rule, since
the note itself flagged this version as the place to revisit it.

### Issue 4 (High, included in this patch) — table+image pages drop the image

`_triage_page()` checks tables first and returns immediately (line 156-157). A
page with both a table and a figure never reaches the image branch, so that
figure never gets a SmolVLM description.

**Prerequisite bug found while fixing this:** even on an image-only page,
`_smolvlm_page()` reuses `_build_vlm_converter()` from `docling_parser.py`,
whose `format_options` dict only contains `InputFormat.DOCX` and
`InputFormat.PPTX`. Docling fills in `InputFormat.PDF` with its own default
`PdfFormatOption()` (`do_picture_description` off by default), so the
"image" tier was silently running plain Docling conversion, not SmolVLM —
regardless of Issue 4. This has to be fixed first or the merge below just
concatenates duplicate plain text.

**Second, adjacent bug:** `_smolvlm_page()`'s exception fallback calls
`pymupdf4llm.to_markdown(pdf, pages=[page_no])`, but `pdf` there is reopened
from `file_bytes`, which is already a single-page PDF (from
`_single_page_bytes()`) — its only valid index is `0`. Passing the original
document's `page_no` throws a page-range error for every page except the
first. Fix: use `pages=[0]`.

## Fixes

### Fix 1 — stamp real page provenance before merging (Issue 1)

Replace `_merge_pages()`'s "join strings → reconvert once" approach with
"convert each page's markdown independently → stamp `prov` → merge documents":

```python
def _merge_pages(self, page_markdowns: list[str], filename: str) -> DoclingDocument:
    combined = DoclingDocument(name=filename.rsplit(".", 1)[0])
    converter = DocumentConverter(allowed_formats=[InputFormat.MD])

    for page_no, md in enumerate(page_markdowns, start=1):  # 1-indexed for humans
        stream = DocumentStream(name=f"page_{page_no}.md", stream=BytesIO(md.encode("utf-8")))
        page_doc = converter.convert(stream).document
        for item in page_doc.texts:
            item.prov = [ProvenanceItem(
                page_no=page_no,
                bbox=BoundingBox(l=0, t=0, r=0, b=0),  # markdown has no real coordinates
                charspan=(0, len(item.text or "")),
            )]
        combined.add_document(page_doc)

    return combined
```

- `core/chunker.py` is untouched — it already reads `item.prov[0].page_no`.
- `bbox` is a required field on `ProvenanceItem` with no meaningful markdown
  equivalent, so a zero-size placeholder is used; only `page_no` is real signal.
- Runs `DocumentConverter.convert()` once per page instead of once total — more
  calls, but each is on a tiny single-page markdown string, so the added cost is
  negligible next to the PyMuPDF4LLM/Docling/SmolVLM extraction that already runs
  per page.
- New imports needed in `pdf_router.py`: `DoclingDocument`, `ProvenanceItem`,
  `BoundingBox` from `docling_core.types.doc`.

### Fix 2 — recalibrate the image-route threshold (Issue 2)

Stop dividing by page area; compare against an absolute character count instead,
which is what the threshold is actually trying to express:

```python
# config.py — replace pdf_text_ratio_threshold with an absolute count
pdf_min_text_chars_for_text_route: int = int(os.getenv("PDF_MIN_TEXT_CHARS_FOR_TEXT_ROUTE", "800"))
```

```python
# pdf_router.py — _triage_page()
has_image = len(page.get_images()) > 0
text_len = len(page.get_text())
if has_image and text_len < settings.pdf_min_text_chars_for_text_route:
    return "image"
```

`800` is a starting point (roughly one short paragraph) — tune against a handful
of real Honeywell manual pages once this lands, since that's the actual
distribution that matters. Existing test `test_triage_returns_text_when_text_dense`
should be updated to use a realistic count (e.g. 3,000 chars) rather than 50,000,
since the whole point of the fix is that realistic text should qualify.

### Fix 3 — correct the stale docstrings (Issue 3)

Update the module docstring (lines 21-26) and the `_docling_page` /
`_smolvlm_page` "v5 scope note" blocks to state that per-page isolation is done
via `_single_page_bytes()`, and that page-provenance is handled in
`_merge_pages()` as of v5.1.

### Fix 4 — merge table + image tiers instead of dropping one (Issue 4)

**4a. `docling_parser.py`** — give the shared VLM converter a real PDF option
(one line, additive; DOCX/PPTX behaviour unchanged):

```python
from docling.document_converter import (
    DocumentConverter, WordFormatOption, PowerpointFormatOption,
    PdfFormatOption,  # NEW

...
return DocumentConverter(
    format_options={
        InputFormat.DOCX: WordFormatOption(pipeline_options=pipeline_options),
```

**4b. `pdf_router.py`** — `_triage_page()` returns a list instead of a single
string, so a page can be both:

```python
def _triage_page(self, page: fitz.Page) -> list[str]:
    routes: list[str] = []
    if len(page.find_tables().tables) > 0:
        routes.append("table")
    has_image = len(page.get_images()) > 0
    text_len = len(page.get_text())
    if has_image and text_len < settings.pdf_min_text_chars_for_text_route:
        routes.append("image")
    return routes or ["text"]
```

`parse()`'s dispatch becomes:

```python
for page in pdf:
    routes = self._triage_page(page)
    if routes == ["text"]:
        page_markdowns.append(pymupdf4llm.to_markdown(pdf, pages=[page.number]))
        continue

    single_bytes = self._single_page_bytes(pdf, page.number)
    parts: list[str] = []
    if "table" in routes:
        parts.append(self._docling_page(single_bytes, filename, page.number))
    if "image" in routes:
        if "table" in routes:
            parts.append(self._picture_descriptions_only(single_bytes, filename, page.number))
        else:
            parts.append(self._smolvlm_page(single_bytes, filename, page.number))
    page_markdowns.append("\n\n".join(p for p in parts if p))
```

New helper — pulls only the picture-description captions (via the same
`_inject_picture_descriptions()` already used for DOCX/PPTX) instead of the
full VLM markdown, so a page with both a table and a figure doesn't get its
body text duplicated:

```python
def _picture_descriptions_only(self, file_bytes: bytes, filename: str, page_no: int) -> str:
    try:
        if self._vlm_converter is None:
            self._vlm_converter = _build_vlm_converter()
        stream = DocumentStream(name=filename, stream=BytesIO(file_bytes))
        doc = self._vlm_converter.convert(stream).document
        _inject_picture_descriptions(doc)
        return "\n\n".join(
            item.text for item in doc.texts
            if item.label == DocItemLabel.CAPTION
            and item.text.startswith("[Figure description]")
        )
    except Exception as exc:
        logger.warning(
            "Picture description failed for page %d of %s: %s. "
            "Keeping table content; skipping image description for this page.",
            page_no, filename, exc,
        )
        return ""
```

And in the existing `_smolvlm_page()` fallback, change
`pymupdf4llm.to_markdown(pdf, pages=[page_no])` to
`pymupdf4llm.to_markdown(pdf, pages=[0])` (second bug under Issue 4).

Imports to add in `pdf_router.py`: `DocItemLabel` (from
`docling_core.types.doc`, alongside the existing `DoclingDocument` import) and
`_inject_picture_descriptions` (from `.docling_parser`, alongside the existing
`_build_vlm_converter` import).
